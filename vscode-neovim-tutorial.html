安装教程 · 从公司电脑迁移过来的记录

把 VSCodeVim 换成 vscode-neovim

这份教程照抄了在公司电脑上真实走过一遍、验证成功的步骤。每条命令都是实际跑过的原样命令,不是网上抄的通用版；带 占位符 样式的地方需要换成你自己电脑上的值。

Windows + WSL VS Code Remote-WSL Neovim ≥ 0.10.0
0

适用范围

默认假设你家里电脑也是 Windows + WSL，VS Code 通过 Remote-WSL 连过去编辑 —— 跟公司这台机器同一套组合，下面的步骤可以整段照搬。

如果家里不是这套组合 如果是纯 Windows（没有 WSL）、macOS 或者 Linux 桌面：跳过所有 useWSL 相关的配置，第 4 步的 vscode-neovim.neovimExecutablePaths.win32（或 .darwin / .linux）直接填本机安装的 nvim 路径就行，其余步骤基本不变。
1

环境自检

先在自己家里的电脑上跑这三条，不要照抄公司电脑查出来的值 —— 发行版名字、apt 版本这些每台机器都可能不一样。

bash · WSL 里跑 
# 1. 自己的 WSL 发行版名字（配置里要填这个）
echo $WSL_DISTRO_NAME

# 2. apt 仓库里的 neovim 版本够不够 0.10.0
apt-cache policy neovim

# 3. systemd 有没有启用，决定能不能用 snap
systemctl is-system-running

公司这台机器实测：发行版是 Ubuntu-22.04，apt 候选版本只有 0.6.1（太旧），systemd 是 running（snap 能用）。家里大概率也会撞到"apt 版本太旧"这个情况，第 2 步已经准备了应对方案。

2

安装 Neovim ≥ 0.10.0

两条路二选一，取决于你能不能拿到一个真正的交互式终端来输 sudo 密码。

方式 A：snap（更省事，前提是有真终端）

bash 
sudo snap install nvim --classic
which nvim   # 确认路径，通常是 /snap/bin/nvim
公司这次踩的坑 这条命令在自动化脚本/AI 会话里跑会失败：sudo: a terminal is required to read the password。必须在一个真正能输密码的终端窗口（Windows Terminal / WSL 自带终端）里手动跑，不能用什么脚本代跑。

方式 B：官方预编译包（免 sudo，公司这次实际走的路）

bash 
curl -fL -o nvim-linux-x86_64.tar.gz \
  https://github.com/neovim/neovim/releases/latest/download/nvim-linux-x86_64.tar.gz

mkdir -p ~/.local
tar xzf nvim-linux-x86_64.tar.gz -C ~/.local --strip-components=1

# 确认装上了
~/.local/bin/nvim --version

把 ~/.local/bin 加进 PATH（编辑 ~/.zshrc 或 ~/.bashrc）：

~/.zshrc 
export PATH=$HOME/bin:$HOME/.local/bin:/usr/local/bin:$PATH

Oh My Zsh 的默认模板里这行本来就有，只是被注释掉了（# 开头），去掉井号即可，不用整行重新加。改完 source ~/.zshrc 或者重开一个终端窗口。

3

卸载 VSCodeVim，装上 vscode-neovim

两者会因为抢注 VS Code 的 type 命令冲突，必须先卸载旧的再装新的，顺序不能反。

bash · 有 code CLI 的话可以直接跑 
code --uninstall-extension vscodevim.vim
code --install-extension asvetliakov.vscode-neovim

也可以在 VS Code 扩展面板里手动搜「VSCodeVim」卸载、搜「VSCode Neovim」（发布者 asvetliakov）装上，效果一样。

装完先别急着测 卸载/安装扩展之后，当前打开的这个 VS Code 窗口用的还是旧的扩展宿主进程 —— 也就是说 VSCodeVim 卡在内存里还没退场，这时候测试会看到"两个插件好像都在生效"的诡异现象。必须 Ctrl+Shift+P → Developer: Reload Window 完整重启一次窗口，才算真正切换过去。
4

配置桥接到 WSL 的 Neovim

最容易踩的坑：改错了 settings.json Remote-WSL 场景下有两份用户设置：VSCodeVim 那套 vim.* 配置存在 "Remote [WSL]" 这份里；但下面这几条 vscode-neovim.* 设置要加到本地（Windows 侧）的 User settings.json —— 两个文件互不相通，改错文件会出现"设置了但完全没反应"。命令面板跑 Preferences: Open User Settings (JSON) 打开的就是本地那份，不要跑带"Remote"字样的那个命令。
json · 本地 User settings.json 
{
  "vscode-neovim.useWSL": true,
  "vscode-neovim.wslDistribution": "你自己的发行版名字，第1步查到的",
  "vscode-neovim.neovimExecutablePaths.linux": "你自己的 nvim 路径，第2步 which nvim 查到的",
  "vscode-neovim.ctrlKeysForNormalMode": [
    "a", "b", "d", "e", "f", "h", "i", "j", "k", "l",
    "m", "o", "q", "r", "t", "u", "v", "w", "x", "y", "z", "/", "]"
  ]
}

ctrlKeysForNormalMode 是普通模式下"哪些 Ctrl 组合键会被转发给真 Neovim"的白名单，默认值不包含 q。上面这份已经手动加上了 q（配合第5步 <C-q> 的 remap）。如果你家里的 .vimrc 还有别的自定义 Ctrl 键 remap，照着这个思路把对应字母也加进这个数组，否则按键会悄无声息地没反应。

5

写 init.lua

Neovim 的配置在 WSL 这一侧：~/.config/nvim/init.lua。下面是这次在公司电脑上验证跑通、零报错的完整版本，照抄即可，再按自己 .vimrc 里的其他自定义内容增补。

lua · ~/.config/nvim/init.lua 
-- 自动引导 vim-plug（Neovim 专用路径，跟老版 vim 的 plug.vim 是分开的）
local plug_path = vim.fn.stdpath('data') .. '/site/autoload/plug.vim'
if vim.fn.empty(vim.fn.glob(plug_path)) > 0 then
  vim.fn.system({
    'curl', '-fLo', plug_path, '--create-dirs',
    'https://raw.githubusercontent.com/junegunn/vim-plug/master/plug.vim',
  })
  vim.cmd('autocmd VimEnter * PlugInstall --sync | source $MYVIMRC')
end

vim.cmd('call plug#begin()')
vim.cmd("Plug 'junegunn/vim-easy-align'")
vim.cmd('call plug#end()')

-- ga 触发对齐（原 .vimrc 里的 vim-plug 插件迁移过来）
vim.keymap.set('x', 'ga', '<Plug>(EasyAlign)')
vim.keymap.set('n', 'ga', '<Plug>(EasyAlign)')

-- matchit 是 Neovim 自带的 runtime 包，让 % 匹配更聪明
vim.cmd('packadd! matchit')

vim.opt.hlsearch = true
vim.opt.backup = true
vim.opt.undofile = true

-- Ctrl+Q 代替被终端占用的 Ctrl+V 进入 Visual Block
-- 需要配合第4步 settings.json 里 ctrlKeysForNormalMode 加上 "q"
vim.keymap.set('n', '<C-q>', '<C-v>')

vim.api.nvim_create_autocmd('FileType', {
  pattern = 'text',
  command = 'setlocal textwidth=78',
})
不用照搬的两条 原 .vimrc 里的 set number / set relativenumber 不要搬进来 —— 行号这类"编辑器外观"由 VS Code 接管，Neovim 自己设置在嵌入模式下不生效。改成 VS Code 原生设置 "editor.lineNumbers": "relative"（跟第4步的 settings.json 加在一起就行）。
6

Reload + 验证清单

Ctrl+Shift+P → Developer: Reload Window，然后依次确认：

  • 打开一个文件，normal / insert 模式切换时光标样式有变化
  • <C-q> 能进入 Visual Block 模式
  • 选中几行文字按 ga 再按 =，等号能自动对齐
  • 敲一条 :join 或 :g/pattern/normal @q，VSCodeVim 从没支持过的命令现在能跑通
7

踩坑记录汇总

apt 里的 neovim 版本太旧

症状：apt install neovim 装完之后 vscode-neovim 报版本不够 / 功能异常。

对策：不要用 apt，走第2步的 snap 或官方 tarball 二选一。

sudo 卡住不动

症状：sudo: a terminal is required to read the password，或者密码怎么输都不生效。

对策：换免 sudo 的官方 tarball 方式（第2步方式B），或者确保是在真正的交互式终端窗口里手动输密码，不是脚本/自动化在代跑。

settings.json 改了但没生效

症状：vscode-neovim.* 设置加了，重启也没用。

对策：检查是不是改到了 "Remote [WSL]" 那份设置里 —— 这些设置要放在本地/Windows 侧的 User settings.json（见第4步）。

自定义 Ctrl 键 remap 没反应

症状：.vimrc 里配的 <C-某键> remap 迁移过来后按了没反应。

对策：检查 ctrlKeysForNormalMode（或插入模式下的 ctrlKeysForInsertMode）白名单里有没有这个字母，默认列表不包含所有字母，没在名单里的键 VS Code 根本不会转发给 Neovim。

vim-plug 第一次冷启动报错

症状：全新环境第一次打开 Neovim，提示 E117: Unknown function: plug#begin。

对策：这是正常的自愈过程 —— init.lua 里的 autocmd VimEnter 会自动触发一次 PlugInstall 并重新加载配置，走完这一轮之后再打开就不会再报错了，不用手动干预。

卸载了 VSCodeVim，感觉还在生效

症状：扩展面板里已经卸载，但按键行为看起来还是老样子。

对策：没有 Reload Window。旧的扩展宿主进程还在内存里跑，卸载要重启窗口才算真正生效（见第3步）。
